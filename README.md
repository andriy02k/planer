# Мій день

Мінімалістичний особистий планувальник українською, розрахований на телефон.

- План на сьогодні та будь-яку наступну дату: сім днів у стрічці та календар.
- Додавання на обраний день, редагування й видалення дій.
- Круглий чекбокс для дій без піддій; круговий прогрес із лічильником для дій із піддіями.
- Окрема сторінка дії з описом та піддіями зі своїми чекбоксами.
- Дані зберігаються в IndexedDB на пристрої. Без акаунтів, хмарної БД і резервних копій.

## Запуск

Потрібен Node.js 22 або новіший.

```sh
npm install
npm run dev
```

Відкрити http://localhost:3000. Для перевірки з телефона в тій самій локальній мережі: http://IP-КОМПʼЮТЕРА:3000 (брандмауер має дозволяти з'єднання).

У поточній робочій папці також завантажено переносний Node.js для локальної перевірки. Якщо Node.js ще не встановлено в Windows, запуск у PowerShell:

```powershell
$env:PATH = (Join-Path $PWD '.tools\node-v22.16.0-win-x64') + ';' + $env:PATH
npm.cmd run dev
```

Папка `.tools` виключена з Git і для деплою не потрібна.

```sh
npm run typecheck
npm run build
npm start
```

## Деплой

Застосунок збирається як статичний сайт у папку `out`. Сервер Next.js і база даних на хостингу не потрібні. Сторінка дії має адресу `/tasks/?id=…`: записи завантажуються з IndexedDB у браузері, тому пряме відкриття та перезавантаження сторінки працюють на статичному хостингу.

### GitHub Pages

1. У репозиторії відкрити **Settings → Pages → Build and deployment → Source** і вибрати **GitHub Actions** замість **Deploy from a branch**.
2. Закомітити й відправити зміни в `master` або `main`, включно з `.github/workflows/pages.yml` і `package-lock.json`.
3. У вкладці **Actions** дочекатися успішного виконання **Deploy to GitHub Pages**. Можна запустити його вручну кнопкою **Run workflow**.

Workflow сам встановить залежності, збере застосунок і опублікує `out`. Префікс адреси (`/planer/` для репозиторію `planer`) береться з налаштувань GitHub Pages автоматично. README публікувати як сайт не потрібно.

Для перевірки такої ж збірки локально в PowerShell:

```powershell
$env:NEXT_PUBLIC_BASE_PATH = '/planer'
npm run build
npm start
```

Відкрити http://localhost:3000/planer/. Для локальної роботи без префікса: видалити змінну `NEXT_PUBLIC_BASE_PATH` перед запуском `npm run dev` або новою збіркою.

### Vercel

Прив'язати репозиторій і обрати стандартні налаштування Next.js. Без префікса `NEXT_PUBLIC_BASE_PATH` застосунок доступний у корені адреси.

## Збереження

Дані прив'язані до браузера та адреси сайту, між пристроями не синхронізуються. Очищення даних сайту їх видаляє. Після зміни домену старі записи залишаються на старій адресі. Дія з піддіями виконана, коли виконані всі її піддії. Для дій без піддій статус встановлюється вручну. Подробиці на сторінці дії згорнуті за замовчуванням.

Для роботи потрібне інтернет-з'єднання, щоб завантажувати сторінки застосунку. Офлайн-кешування не реалізовано.

## Стек

Next.js, React, TypeScript, звичайний CSS, браузерний IndexedDB API. Без сторонніх UI-бібліотек і зовнішніх шрифтів.
